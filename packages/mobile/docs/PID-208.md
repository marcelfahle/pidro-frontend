# PID-208: blocked on the friends-list contract

Implementation is paused before changing the app. The requested friend picker
cannot use an existing friends API on the current backend `main`.

## Verified contracts

- [Backend PID-208](https://github.com/marcelfahle/pidro-backend/pull/88) is merged.
  It supports held seat plans, host hold/release endpoints, `held_for` profiles,
  and position-bound invites. Its PR body overrides the original contract.
- REST/readiness seats remain position-keyed objects; lobby-channel and invite
  preview seats remain arrays.
- `GET /api/v1/auth/me` returns `data.seat_invitations`, containing
  `{ code, position, host_id }`. These are live holds, and `code` is the
  four-character room code for a normal join, not an invite redemption code.
- That PR explicitly says no friends notifications, push registration, or invite
  inbox exists. Push delivery is deferred. The app can consume the new in-app
  invitation list without adding push registration.

## Missing prerequisite

[PID-24](https://linear.app/boldvideo/issue/PID-24) is a legacy add-friend endpoint
for `/v2/users/:id/friends/:friend_id` and `/v3/users/:id/friends/:friend_id`.
It uses integer Classic IDs; it does not specify a friends-list response with
the UUIDs required by the new backend's seat holds.

The current backend router has no friends route, and the mobile Friends screen
is a placeholder. No list contract supplies friend UUIDs, names, avatars,
online status, or last-played timestamps. Inventing a client list, treating
other players as friends, or using Classic IDs as UUIDs would not fulfill the
ticket.

To resume, provide the supported authenticated friends-list endpoint and its
response contract, including the mapping to current user UUIDs and the source
of online/last-played information. If that service does not exist, it needs a
separate backend prerequisite. Push notification delivery also remains a
server dependency; there is no emitted notification to follow today.

No UI, dependencies, native configuration, or backend behavior has changed.
This branch must not be merged as the completed PID-208 feature.
